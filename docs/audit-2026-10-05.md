## P1 findings

### AUDIT-09 — Build cleanup deletes application data

Status: **closed 2026-10-06**. Application data is preserved; isolated dry-run and deletion regressions pass. See [remediation evidence](audit-remediation-2026-10-06.md#audit-09--closed). The evidence below describes the original defect.

Evidence: `scripts/clean.ps1:198-220` makes `-All` recursively delete `%LOCALAPPDATA%/OnlyWinget`, including the workspace database, source preferences, settings and logs. `run.ps1` forwards `-All`; operational docs describe cleaning outputs without documenting this data reset.

Impact: a developer cleanup can erase real user presets and settings outside the checkout.

Close when: repository cleanup preserves application data; any separately supported data-reset action has an explicit contract and protection appropriate to that action. Verify with a dry run and isolated sentinel fixtures, never real user data.

### AUDIT-10 — UI validation targets unrelated dialogs and processes

Status: **implemented 2026-10-06; interactive validation pending**. Global window/process actions are removed; native ownership regression passes. See [remediation evidence](audit-remediation-2026-10-06.md#audit-10--implemented-interactive-validation-pending). The evidence below describes the original defect.

Evidence: `scripts/ui-test.ps1:127-145` enumerates all windows, sends Escape/WM_CLOSE to any Open/Apri or `#32770` dialog, then terminates every `PickerHost` process by name.

Impact: running the test can close another application's file picker/dialog and interrupt unrelated user work.

Close when: all picker actions are tied to the test app's window ownership/session; remove global process termination. Validate with an unrelated picker kept open beside the app.

### AUDIT-11 — Certificate recovery silently resets every WinGet source

Status: **closed 2026-10-06**. Certificate failures return diagnostics without automatic reset/retry; six new regressions pass. See [remediation evidence](audit-remediation-2026-10-06.md#audit-11--closed). The evidence below describes the original defect.

Evidence: `ProcessWingetCommandRunner.cs:58-73` reacts to certificate mismatch during an ordinary command by executing `winget source reset --force` and retrying. Microsoft documents that an untargeted reset removes non-default sources and requires elevation [S1]. This runner is shared by discovery and execution; discovery fans out concurrent source requests.

Impact: a search/update/install failure can destroy custom source configuration; parallel failures can issue overlapping global resets.

Close when: certificate failure returns an actionable diagnostic. Any explicit recovery is scoped, preserves configuration and is serialized. Add regressions proving read-only failure never invokes global reset.

### AUDIT-12 — Release commit and verification are not enforced

Status: **implemented 2026-10-06; hosted validation pending**. Tag/version/SHA, full gate and required supported assets are enforced in the release job. Isolated regressions and actionlint pass. See [remediation evidence](audit-remediation-2026-10-06.md#audit-12--implemented-hosted-validation-pending). The evidence below describes the original defect.

Evidence: `.github/workflows/release.yml:23-57` checks out the triggering ref without using manual `tag_name`, then publishes under that supplied tag. It packages without running or requiring the build gate. Tag push also publishes independently of the gate. `docs/release.md` instead requires verification of the exact release commit. Checkout defaults to the event ref/SHA [S2].

Impact: manual dispatch can attach binaries from a branch to a different existing tag, and failed/unrun verification does not prevent publication.

Close when: resolve and checkout the exact release tag/commit, validate tag/project version correspondence, require successful verification for that SHA, and fail on missing required release assets. Test manual dispatch with different branch/tag commits.

## P2 findings

### AUDIT-13 — MSIX path is unfinished but runs on every release

Status: **closed 2026-10-06**. NSIS/portable distribution confirmed, unused MSIX task/script/manifest retired, obsolete upload paths removed and portable upload added. Packaging passes. See [remediation evidence](audit-remediation-2026-10-06.md#audit-13--closed). The evidence below describes the original defect.

Evidence: `scripts/package-msix.ps1:12-53` does not assert native command exit codes or a produced MSIX, makes `winapp` optional, searches an output directory it never explicitly passes to packaging, and retains an extracted signing PFX. `Package.appxmanifest:13-38` stays at version 1.0.0.0, retains `$targetnametoken$` and names four missing logo assets. Release invokes this path unconditionally; neither release nor build-gate removed old MSI globs, and build-gate omits the supported portable ZIP.

Close when: align distribution with the documented NSIS/portable contract by retiring unused MSIX remnants, or explicitly complete and document MSIX. A retained path must fail on missing tools/output, use valid staged manifest/assets/version, clean up signing material and verify signatures. Upload both supported artifacts and remove obsolete MSI paths.

### AUDIT-14 — Source refresh overrides saved choices and lacks privilege handling

Status: **Closed on 2026-10-06**. Historical evidence below; implementation and verification: [remediation](audit-remediation-2026-10-06.md#audit-14--closed).

Evidence: `OnlyWingetApplication.Sources.cs:17,181-229` always repairs/re-adds official sources and removes their disabled preferences, even when `DefaultSourcesConfigured` is true. `SetSourceEnabledAsync:104` writes the flag's default false. The test `EnsureOfficialSourcesConfigured_EnablesOfficialSourcesByDefault` explicitly expects an already-saved disabled source to be re-enabled. The UI enables add/remove/reset without checking `IsElevated`; execution uses the normal process runner although those source commands require elevation [S1].

Close when: initialize defaults once, preserve later user choices and configuration on refresh/restart, retain the initialization flag, and show or implement the required privilege path for mutations. Cover disable-refresh-reload, failed preference save, non-admin source changes and remove/add failure without losing the original source.

### AUDIT-15 — Cancellation propagation has remaining holes

Status: **Closed on 2026-10-06**. Historical evidence below; implementation and verification: [remediation](audit-remediation-2026-10-06.md#audit-15--closed).

Evidence: `OnlyWingetApplication.Sources.cs:26-64,114-126` captures the caller token in a zero-argument mutation delegate, so the linked token cancelled by the global tracker does not reach the mutation. `ResetSourcesAsync:68-72` saves outside `RunAsync` after its final notification. `WingetPackageResolver.CheckInstalledStatusAsync` and capability probes catch cancellation as an ordinary failure/unavailability.

Close when: source operations and preference changes share the guarded lifetime and linked token; cancelled checks propagate cancellation, never report not-installed/unavailable. Use blocking stub regressions for every source mutation and installed-status/capability cancellation; preserve actionable errors on save failure.

### AUDIT-16 — State snapshots and workspace changes use inconsistent guards

Evidence: `OnlyWingetApplication.cs:75,205-220` locks snapshots/synchronous changes with `stateLock`; async workflows mutate the same lists/selection/workspace without that lock. Search/update fan-out instead locks `searchResults`/`updates`. Synchronous preset changes are allowed during async work; `ToPresetsState` disables them for only ExecutingOperation/ValidatingPackages. A preset change during another operation attempts autosave, which the global async guard rejects.

Impact: snapshots can race collection updates; edits during load can be overwritten and edits during other operations can remain unsaved.

Close when: shared-state publication uses one coherent guard, persistent mutations are serialized/rejected while busy, and successful UI edits cannot silently miss persistence. Exercise concurrent snapshots/selections, delayed workspace load and edit-while-searching with deterministic barriers.

### AUDIT-17 — WinGet rescan loses outcomes and errors

Evidence: `WingetUpdatesViewModel.cs:64-70` rescans after apply even if apply failed. `OnlyWingetApplication.Updates.cs:26-27` immediately clears update rows and `lastOperationResults`; `RunAsync` clears the user error. Cancelling a batch also throws before the executor returns accumulated results, so prior completed items are not committed to activity/results.

Close when: preserve completed/failed/cancelled batch outcomes, rescan according to the actual result and retain actionable failures/retry information. Verify mixed failure/success, cancellation after one completed package, failed rescan and successful rescan. This is the WinGet counterpart of the completed Windows Update AUDIT-07 scope.

### AUDIT-18 — Preset edit validation rejects the existing package

Evidence: `PresetsViewModel.cs:265-269` checks duplicates by ID alone, including the item currently edited; `PresetsPage.xaml.cs:210` disables save using this validation. `PrepareEditFields` populates that same ID. Domain identity is ID plus source, while the UI prevents the same ID from another source. The XAML and constructor also both attach `OnEditPackageFlyoutOpened`.

Close when: edit validation excludes the current identity, accepts source-only edits, matches domain identity semantics and wires the flyout once. Validate source-only edits, same-ID/different-source additions and a real duplicate.

### AUDIT-19 — Unsaved-edit guard proceeds after failed apply

Evidence: `PresetsPage.xaml.cs:311-341` always returns true after ExecuteCommandAsync and hides the flyout; `PresetsViewModel` clears fields even after rejected add/edit. Both navigation guards return true on exceptions. `MainWindow.Navigate:381-385`, used by the tracker, shows the target directly without awaiting the guard. Active-preset changes and window close also do not route through pending-edit confirmation.

Close when: propagate action/save success, retain fields and block navigation on failure, and route supported exit/navigation paths through one guard. Test failed validation/save, tracker navigation, preset switching and closing with pending edits. Avoid prompting for unchanged edits.

### AUDIT-20 — Native Windows Update display disagrees with fallback

Evidence: `ComWindowsUpdateService.cs:190` prefixes KB IDs with KB; `PresentationStateMapper.cs:201` prefixes them again, producing KBKB values. Native rows use the literal severity Important (`:214`) instead of `MsrcSeverity` [S3], and use potential installation reboot behavior as current `RebootRequired`; the fallback reads the actual update fields.

Close when: both adapters return the same canonical KB/severity/reboot semantics and presentation applies formatting once. Add deterministic mapper/adapter regressions; check native/fallback parity during the existing controlled WUA validation.

### AUDIT-21 — Parallel legacy and Serilog file logging conflict

Evidence: `AppComposition.cs:39-42` always enables an Information-level file sink and a forwarding AppDiagnostics sink. `AppDiagnostics.cs:80` also appends to a daily log, and `:114-140` deletes log files while Serilog still owns its active file. App settings change only AppDiagnostics filters. File I/O failures are swallowed. Serilog's file sink has its own file ownership/retention behavior [S4].

Close when: use one file writer and a separate UI buffer; apply diagnostic enable/level settings consistently, make clear/export outcomes accurate and preserve original event levels. Test logging disabled, Verbose selection, clear while running and repeated writes without duplicates/lost diagnostics.

### AUDIT-22 — Missing localization keys and unfinished log dialog UX

Evidence: static lookup found missing `Logs_ClearConfirm_Title`, `Logs_ClearConfirm_Message`, `Command_Clear`, `Command_Cancel` and seven `State_*` keys referenced by `OperationTrackerControl`. `TextResources.Get:463-468` returns the key for a missing translation, so `??` English fallbacks never apply. `LogViewerDialog.xaml` contains English-only labels/names and hardcoded badge colors. `OnClearClicked` attempts to open another ContentDialog while the log dialog is already open; the WinUI dialog contract permits only one dialog per UI thread [S5].

Close when: add EN/IT resources through TextResources, theme-aware badges and a valid clear-confirmation flow. Check all literal localization references, both languages, high contrast and actual clear confirmation in the running UI.

### AUDIT-23 — Protocol activation ends at a log message

Evidence: `App.xaml.cs:73-80` parses install/show/search requests and logs them, but never navigates, populates a query, resolves a package or invokes an approved action. Startup nevertheless registers the protocol in HKCU. NSIS uninstall removes no protocol registration; portable launches can redirect the handler to a subsequently removed executable.

Close when: complete only the intended protocol actions with validation and appropriate confirmation, or retire the unused advertised registration/parser contract. Queue any retained request until startup is ready and clean registration only when owned by that executable. Test all valid actions, malformed URLs and installer/portable coexistence.

### AUDIT-24 — Packaging does not implement its documented atomic output

Evidence: `scripts/package.ps1:206-224` passes the final distribution setup path to NSIS, then deletes/recreates the final ZIP. No staging-to-final promotion is used. `docs/release.md:25` and `scripts/README.md:44` claim atomic staging. The per-worktree lock exists; it does not protect readers from partial/replaced final files.

Close when: generate/validate both artifacts under staging, then promote them while preserving the previous valid release on failure. Verify simulated NSIS/compression failure and interrupted packaging against existing sentinel release artifacts.

### AUDIT-25 — Uninstaller terminates every same-name app instance

Evidence: `OnlyWinget.nsi:121` executes `taskkill /F /IM OnlyWinget.exe`. `ScriptHelpers.ps1` also identifies locks and force-stop candidates by name across all installations, even for build output in one checkout.

Close when: target only the executable path/installation being modified and use a graceful-close/bounded wait where possible. Verify a portable or second-checkout instance remains running while removing/validating another installation.

### AUDIT-26 — Uninstall unnecessarily depends on remote package resolution

Evidence: `OnlyWingetApplication.Execution.cs:88` runs `ValidatePackageAsync` for every action, including Uninstall. That requires an enabled source and successful `winget show` before the local uninstall command can run.

Impact: locally installed software cannot be uninstalled through a preset if its catalog entry disappeared, its source is disabled or the catalog is unavailable.

Close when: validate uninstall identity through the appropriate local installed-package path, retaining safe discrete arguments. Cover unavailable/disabled source, removed manifest and genuine local ambiguity; consult the supported uninstall contract [S6].

### AUDIT-27 — Verification can report success without testing the claim

Evidence: all five Smoke methods return early and count as Passed when not enabled; two live search tests duplicate the same CLI flow. `scripts/test.ps1` suppresses all dotnet output even in Full mode, losing compilation diagnostics when no TRX exists. `ui-test.ps1:32-39` checks only the final native exit code of a block; earlier failure can be overwritten. Focus/toggle/picker/layout checks often assert invocation or screenshot production rather than the named state/mutation invariant. `validate-installed-startup.ps1` and lifecycle startup accept an early exit with code 0 without proving a responsive window.

Close when: distinguish executed/skipped live tests, retain failure logs, check each native result and assert observable state and responsive-window invariants. Add coverage for the newly listed source/VM/lifecycle paths. Verify intentional early failure, early-zero app exit, unchanged focus and failed toggle restoration are reported as failures.

### AUDIT-31 — Upgrade validation cannot detect removed files from old releases

Evidence: `validate-installer-lifecycle.ps1` generates a PreviousVersion setup from the current checkout when no real previous setup is supplied. This tests a version label change with the same payload. The generated ownership include removes only the current payload; NSIS upgrade overwrites files without reconciling the previous distributed-file list. Files removed between versions therefore remain installed and are unknown to the new uninstaller.

Close when: use a genuine previous-release fixture with at least one removed/renamed file, reconcile files owned by that release while preserving unrelated files, and verify upgrade followed by uninstall. Extend the AUDIT-01 ownership regression to version transitions without reintroducing recursive deletion.

## P3 findings

### AUDIT-28 — Unused implementations and disconnected flows remain

Evidence: `JsonWorkspaceStore` remains a complete read/write implementation although production composition selects SQLite and references only its legacy path; legacy JSON reading remains necessary until the migration contract changes. DPAPI services/interfaces are registered but have no product consumer. `RetryFailedOperationsAsync` has tests but no UI caller/command. `TogglePresetPackage` duplicates `TogglePresetPackageInclusion`. SQLite entity metadata such as Description/PackageName/timestamps is not round-tripped by WorkspaceState; full replacement recreates IDs/timestamps on every save. The secret-store corrupt-load fallback can overwrite existing content on a subsequent save if this dormant service is activated.

Close when: identify the intended consumer for each retained surface, remove unused implementations/duplicate APIs or connect only already-required flows. Preserve the legacy migration reader and fixtures. If secret storage is retained, protect failed loads against overwrite. Do not add features solely to justify unused code or remove dependencies without checking consumers.

### AUDIT-29 — Developer instructions and media generation retain old architecture

Evidence: `skills/onlywinget/SKILL.md` still describes WinGet native COM; `.agents/skills/onlywinget/SKILL.md` still names WiX in its description. `docs/architecture.md` claims COM capability probing, ItemsRepeater tables, messenger/relay-command use in every VM and `secrets.dpapi`; current code differs. `install-skills.ps1` copies root skills only if the destination is absent, leaving contradictory copies. `update-media-assets.ps1` defaults to an external machine-specific image and generates WixUIBanner/WixUIDialog instead of the HeaderBanner/WelcomeDialog used by NSIS; `align-logos.ps1` invokes that stale default without input.

Close when: establish one maintained source for project skills/docs, align facts with actual consumers, use a repo master logo or required argument and generate only consumed NSIS assets. Verify media generation on an isolated output directory and audit residual WiX/COM/machine-path references.

### AUDIT-30 — Landing download flow is stale and selects arbitrary artifacts

Evidence: `landing/index.html:47-50` links version 1.0.1; the app/setup artifacts are 1.0.2. Local landing/build still contains 1.0.1; this does not establish the currently deployed site's state. `generate-landing-setup.ps1` uses Select-Object -First 1 without matching the current version while packaging retains old distribution versions. Social copy advertises choosing exact package versions, a control the application does not offer.

Close when: select exact artifacts from the current project's version, update both download links and remove unsupported feature claims. Validate links and payload versions in the prepared website; verify deployed status separately before calling the release current.
